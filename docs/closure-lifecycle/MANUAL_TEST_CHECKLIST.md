# MANUAL_TEST_CHECKLIST — 1·2·3단계

자동 검증은 Node/jsdom과 Chromium의 base·concurrent 조합에서 수행했다.
체크한 항목은 로컬 모의 요청을 사용하는 3단계 시연에서 완료했다. 실제 서비스 검증과 구분한다.

- [ ] Chromium·Firefox·Safari에서 취소를 무시하는 느린 검색 A 다음에 B를 실행하고 결과·오류·pending이 B를 따른다.
- [ ] 위젯 제거 직후 응답이 도착해도 observer가 실행되거나 DOM이 되살아나지 않는다.
- [ ] 네트워크 취소가 서버 저장의 롤백을 의미하지 않는다는 설명을 실제 저장 API와 대조한다.
- [ ] 같은 태스크의 Custom Element 이동에서는 인스턴스와 작업이 유지되고 실제 제거 때 정리된다.
- [ ] 폐기 후 비동기로 얻은 자원은 즉시 정리되며, 정리 오류가 나도 다른 등록과 자식이 정리된다.
- [ ] CSP가 적용된 호스트에서 코어와 별도 실험 UMD를 로드하고 동작을 확인한다.
- [ ] 실제 ESM 앱에서 헬퍼를 사용하지 않을 때와 사용할 때의 최종 다운로드 크기를 비교한다.

- [ ] 실제 편집기에서 숨김·재활성화를 반복해 draft·undo·DOM이 유지되고 폴링과 구독이 중복되지 않는다.
- [ ] 숨김 중 검색은 취소되고 저장은 계속되며, 재활성화에 최신 모델을 반영한다.
- [ ] 숨김·재활성화 시 포커스·선택 영역과 접근성을 확인한다. 자동 복원은 구현하지 않았다.
- [ ] 영상·iframe의 브라우저 활동이 숨김만으로 멈추지 않는지 확인하고 필요한 정지를 `onActive` cleanup에 연결한다.

- [x] Chromium의 두 코어·두 호스트에서 초안·undo·DOM 동일성과 숨김 중 draw 중단을 확인한다.
- [x] 취소를 무시하는 모의 검색 A가 검색 B 또는 다음 활동 세대의 결과를 덮지 않는다.
- [x] 모의 저장은 숨김 중 완료하고 재활성화에 표시하며, 다시 시작하지 않는다.
- [x] 반복 숨김·재활성화에서 폴링·구독이 0/1로 유지되고 최신 외부 상태로 연결된다.
- [x] 기존 element의 같은 태스크 이동은 인스턴스를 유지하고 영구 제거 후 재연결은 새 인스턴스를 만든다.
- [x] 빌드한 base 시연을 데스크톱·390 px 모바일에서 확인한다.

2단계는 명시적인 관리 갱신과 활동 범위를 사용하는 독립 루트가 대상이다.
자식의 독립 renew, portal, 기존 effect 및 state-ref 커넥터의 활동 중단은 자동으로 제공하지 않는다.
