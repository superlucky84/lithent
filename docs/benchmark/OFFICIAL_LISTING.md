## 4. 계산 방법

결과 페이지는 표를 브라우저에서 계산한다. 같은 계산을 `webdriver-ts-results/src/Common.ts`대로 다시 했다.

- 항목마다 각 구현의 중앙값을 keyed 구현 중 가장 빠른 중앙값으로 나눈 배수
- CPU 9항목의 가중 기하평균. 가중치는 `computeGeometricMean`에 적힌 값
  (`0.643, 0.561, 0.564, 0.193, 0.132, 0.528, 0.564, 0.551, 0.423`)

이 계산을 Chrome 156 데이터에 돌리면 결과 페이지의 값(lithent 1.29·97위, React hooks 1.56, Preact classes 1.31, Lit 1.28 등)이
그대로 나온다. 그래서 Chrome 158 값도 페이지와 같다고 본다.

## 5. 읽는 법

- **React 대비**: 모든 CPU 항목이 같거나 빠르다. 행 교환은 14.4 대 87.4ms, 10k 생성은 254.9 대 341.6ms다.
  전송 크기는 5.9 대 51.4kB(약 1/9), 첫 페인트는 52.4 대 228.9ms, 메모리도 모든 항목에서 적다.
- **Preact·Vue·Lit 대비**: 같은 층이다(1.27~1.31). 우위가 아니라 동급이다. Chrome 158에서 첫 페인트는 이 넷 중 가장 빠르다
  (52.4 / Preact classes 53.1 / Lit 58.6 / Vue 94.8).
  [위젯 비교](../widget-compare/)에서 크기 차이가 Preact·Lit 대비 약 10%였던 것과 같은 결론이다.
- **약한 항목**: 10번째 행 갱신(139위), 1k 메모리(128위), 행 교환(125위), 행 선택(124위). 부분 갱신과
  메모리다. 이 항목들은 [STATUS](./STATUS.md)·[HANDOFF](./HANDOFF.md)의 후보 실험에서 이미 여러 번 시도했고
  가중 점수를 세션 흔들림(약 ±2%) 밖으로 움직이지 못했다.
- **#1261 주석**: 행 데이터에 `cacheUpdate`를 붙인 앱이라 "수동 (v)dom 캐싱" 주석이 붙어 있다. 주석 없는
  행 컴포넌트 + `memo` 앱은 가중 약 +3%(1.31 → 1.35 수준)여서 유지하기로 했다
  ([HANDOFF](./HANDOFF.md) 첫 절, DC-29). 이 숫자를 인용할 때는 주석이 있다는 사실을 같이 적는다.
